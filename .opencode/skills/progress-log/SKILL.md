# Progress Log

Append a standardized development record to `progress.txt` at the repo root
every time a task from `DEVELOPMENT_PLAN.md` is completed. Never rewrite or
reorder existing entries; always append.

## When to use

- A task listed in `DEVELOPMENT_PLAN.md` has just been completed and verified.
- The user asks you to "log progress", "record this task", or "update progress".

## Before logging

1. Confirm the task actually finished and, when applicable, that its
   verification step (build, lint, test, manual check) passed.
2. Identify the task ID (e.g. `T3.2`), its title, and the phase it belongs to.
3. Collect the files created/modified and any commands run for verification.

## Entry format

Append the following block exactly (no emojis), separated from the previous
entry by a single blank line:

```
--------------------------------------------------------------------------------
[<ISO-8601 UTC timestamp>] TASK <task-id> - <task title>
--------------------------------------------------------------------------------
Phase      : <phase number and name>
Status     : DONE
Summary    : <1-3 sentences: what was implemented and why>
Files      : <comma-separated repo-relative paths, or "none">
Verification: <command(s) run and result, or "not applicable">
Next       : <next task id and title, or "Awaiting user instruction">
```

### Field rules

- Timestamp: UTC, format `YYYY-MM-DDTHH:MM:SSZ`.
- Status: one of `DONE`, `DONE_WITH_ISSUES`, `BLOCKED`.
- Summary: past tense, concise, no marketing language.
- Files: repo-relative with forward slashes; use `none` if no files changed.
- Verification: quote the exact command and a short outcome.
- Next: reference the following task in `DEVELOPMENT_PLAN.md`, or
  `Awaiting user instruction` if the workflow is paused.

## Procedure

1. If `progress.txt` does not exist, create it with the header block below,
   then append the entry.
2. If it exists, read the last entry to confirm continuity, then append.
3. Write the entry atomically (full-file write preserving prior content).
4. Report back in one line: `Logged <task-id> to progress.txt.` and stop.

## progress.txt header

The first time the file is created, start it with:

```
================================================================================
self-docs - Development Progress Log
Append-only. One entry per completed task from DEVELOPMENT_PLAN.md.
Generated by the progress-log skill.
================================================================================
```

## Example entry

```
--------------------------------------------------------------------------------
[2026-09-17T16:45:00Z] TASK T1.1 - Repository scaffolding and tooling
--------------------------------------------------------------------------------
Phase      : 1 - Foundation
Status     : DONE
Summary    : Initialized the monorepo layout with frontend/ and backend/
             directories, root README, and shared .gitignore.
Files      : frontend/package.json, backend/go.mod, .gitignore,
             README.md
Verification: `go build ./...` and `npm install` both completed cleanly.
Next       : T1.2 - PostgreSQL schema and migrations
```
