# self-docs - Data Model

Domain model for the persistence layer described in `PRD.md` section 6.1.
Target database: PostgreSQL 16+. All primary keys are UUID v4 generated by the
application or `gen_random_uuid()` (via `pgcrypto`).

## 1. Entity overview

```
documents ──< document_tags >── tags
    │
    └── parent_id (self reference, Project Notes hierarchy)

activity_logs ──> documents (nullable soft reference)
settings (key/value; stores the master password hash)
```

## 2. Enumerations

### document_section

The four pillars from PRD 3.2. Stored as a PostgreSQL enum.

| Value          | Label              | Hierarchy          | Visibility |
| -------------- | ------------------ | ------------------ | ---------- |
| `workflow`     | Workflows & Guides | flat               | public     |
| `project_note` | Project Notes      | nested (parent_id) | public     |
| `cheat_sheet`  | Cheat Sheets       | flat               | public     |
| `private`      | Private Archive    | flat               | restricted |

`private` documents are excluded from home listings, tag aggregation, activity
feeds, and global search. Only the master-password session may read or write
them.

### activity_action

| Value      | Description                              |
| ---------- | ---------------------------------------- |
| `created`  | A document was created                   |
| `updated`  | A document's content or metadata changed |
| `deleted`  | A document was deleted                   |
| `imported` | One or more documents were imported      |
| `unlocked` | The Private Archive was unlocked         |

## 3. Tables

### 3.1 documents

| Column          | Type               | Constraints                                        | Notes |
| --------------- | ------------------ | -------------------------------------------------- | ----- |
| `id`            | `uuid`             | PK, default `gen_random_uuid()`                    | |
| `title`         | `text`             | NOT NULL, length 1..300                            | |
| `slug`          | `text`             | NOT NULL, lowercase kebab                          | derived from title; uniqueness scoped (see below) |
| `content`       | `text`             | NOT NULL, default `''`                             | Markdown source |
| `excerpt`       | `text`             | NULL                                               | optional summary for cards/lists |
| `section`       | `document_section` | NOT NULL                                           | |
| `parent_id`     | `uuid`             | NULL, FK -> `documents(id)` ON DELETE CASCADE      | only valid for `project_note` |
| `position`      | `integer`          | NOT NULL, default `0`                              | sibling ordering |
| `is_private`    | `boolean`          | NOT NULL, default `false`                          | derived: `section = 'private'`; denormalized for indexing |
| `search_vector` | `tsvector`         | NULL                                               | generated/maintained for FTS |
| `created_at`    | `timestamptz`      | NOT NULL, default `now()`                          | |
| `updated_at`    | `timestamptz`      | NOT NULL, default `now()`                          | bumped by trigger/app on update |

Rules and indexes:

- `CHECK (section = 'project_note' OR parent_id IS NULL)` — only Project Notes
  may be nested.
- `CHECK (parent_id <> id)` — a document cannot be its own parent.
- Prevent cycles in the Project Notes tree at the application layer; the DB
  guard is the self-reference check above plus FK cascade.
- Sibling slugs are unique within the same parent. Because PostgreSQL treats
  `NULL` values as distinct in unique indexes, use two partial unique indexes
  plus a sentinel: `UNIQUE (parent_id, slug)` for nested documents, and
  `UNIQUE (section, slug) WHERE parent_id IS NULL` for root-level documents.
- Indexes: `idx_documents_section`, `idx_documents_parent_id`,
  `idx_documents_updated_at DESC`, `idx_documents_is_private`,
  `idx_documents_search_vector` (GIN).
- `search_vector` weights: `title` = A, tags are not stored here (joined at
  query time), `content` = B. Expected expression:
  `setweight(to_tsvector('simple', coalesce(title,'')), 'A') ||
   setweight(to_tsvector('simple', coalesce(content,'')), 'B')`.

### 3.2 tags

| Column       | Type          | Constraints                        | Notes |
| ------------ | ------------- | ---------------------------------- | ----- |
| `id`         | `uuid`        | PK, default `gen_random_uuid()`    | |
| `name`       | `text`        | NOT NULL, UNIQUE, length 1..64     | canonical display form |
| `normalized` | `text`        | NOT NULL, UNIQUE, lowercase        | lookup key; strips `#` |
| `created_at` | `timestamptz` | NOT NULL, default `now()`          | |

Indexes: `idx_tags_normalized` (unique), `idx_tags_name`.

### 3.3 document_tags

Join table (many-to-many).

| Column        | Type   | Constraints                                        |
| ------------- | ------ | -------------------------------------------------- |
| `document_id` | `uuid` | NOT NULL, FK -> `documents(id)` ON DELETE CASCADE   |
| `tag_id`      | `uuid` | NOT NULL, FK -> `tags(id)` ON DELETE CASCADE        |

Primary key: `(document_id, tag_id)`. Index: `idx_document_tags_tag_id` for
reverse lookups (tag -> documents, popularity counts).

### 3.4 activity_logs

| Column           | Type              | Constraints                          | Notes |
| ---------------- | ----------------- | ------------------------------------ | ----- |
| `id`             | `uuid`            | PK, default `gen_random_uuid()`      | |
| `action`         | `activity_action` | NOT NULL                             | |
| `document_id`    | `uuid`            | NULL, FK -> `documents(id)` ON DELETE SET NULL | soft reference |
| `document_title` | `text`            | NULL                                 | snapshot so the feed survives deletes |
| `section`        | `document_section`| NULL                                 | snapshot for display/filtering |
| `actor`          | `text`            | NOT NULL, default `'user'`           | single-user local-first |
| `created_at`     | `timestamptz`     | NOT NULL, default `now()`            | |

Indexes: `idx_activity_logs_created_at DESC`,
`idx_activity_logs_document_id`.

Feed queries join to `documents` and filter `section <> 'private'`; snapshots
let a deleted document still render, but private actions are never written to
the feed (see below).

### 3.5 settings

Key/value store for application-level secrets and flags.

| Column       | Type          | Constraints                     | Notes |
| ------------ | ------------- | ------------------------------- | ----- |
| `key`        | `text`        | PK                              | e.g. `master_password_hash` |
| `value`      | `text`        | NOT NULL                        | |
| `updated_at` | `timestamptz` | NOT NULL, default `now()`       | |

Known keys:

- `master_password_hash` — bcrypt/argon2 hash for the Private Archive
  (PRD 3.2, 5). Never returned by any endpoint.

## 4. Referential actions

- Deleting a `project_note` cascades to its children (`parent_id` FK).
- Deleting a document cascades its `document_tags` rows and sets
  `activity_logs.document_id` to NULL while retaining the title snapshot.
- Deleting a tag removes its `document_tags` rows only.

## 5. Full-text search

Search runs against `documents.search_vector` combined with tag names:

```sql
SELECT d.*,
       ts_rank(d.search_vector, websearch_to_tsquery('simple', $1)) AS rank
FROM documents d
WHERE d.is_private = false
  AND d.search_vector @@ websearch_to_tsquery('simple', $1)
ORDER BY rank DESC, d.updated_at DESC;
```

- `websearch_to_tsquery` tolerates natural query syntax.
- The `simple` dictionary is used so technical terms, code identifiers, and
  mixed-language content are matched literally.
- The `is_private = false` predicate is mandatory (PRD 3.3 critical
  restriction) and is enforced in a single repository method so no call site
  can forget it.
- Tag matching is additive: a document matches if its title/content vector
  matches or if it has a tag whose `normalized` value matches the query.

## 6. Private Archive isolation

Invariants enforced at the repository layer:

1. `is_private = true` documents never appear in list, tag, dashboard,
   activity, or search results.
2. Write paths reject `section = 'private'` unless the request carries a valid
   master-password session.
3. `activity_logs` rows are not written for private-only mutations, so the feed
   cannot leak their existence or titles.
4. The master password hash lives only in `settings` and is compared with a
   constant-time hash verification.

## 7. Future extensions

- **Encryption at rest (PRD 5):** add `content_encrypted bytea` and a
  `content_nonce` column; the plaintext `content` column is nulled for private
  documents. `search_vector` would then exclude private content entirely.
- **Document versioning:** a `document_revisions` table keyed by `document_id`
  and `revision` to support history and restore.
- **Attachments:** a `document_assets` table for images referenced in Markdown.
